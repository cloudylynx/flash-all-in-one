# Flash All In One 插件开发指南

插件系统让任何人可以给工具箱加功能，而不需要改主程序代码。

---

## 一、插件是什么

一个插件就是一个目录，里面装：

```
my-plugin/
├── plugin.json          必需：清单
└── tools/               可选：可执行工具
    ├── windows/
    │   └── mytool.exe
    └── linux/
        └── mytool
```

打包成 zip 后在「插件管理」页面导入即可。

## 二、最小可用插件

### 2.1 plugin.json

```json
{
  "id": "hello-world",
  "name": "Hello World",
  "version": "1.0.0",
  "description": "最小插件示例",
  "author": "你的名字",
  "icon": "star",
  "category": "工具",
  "tools": [
    {
      "name": "echo",
      "path": "tools/windows/echo.exe",
      "platform": "windows",
      "executable": true
    }
  ],
  "ui": {
    "inputs": [],
    "cards": [
      {
        "title": "演示",
        "actions": [
          {
            "label": "打个招呼",
            "tool": "echo",
            "args": ["Hello"],
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

### 2.2 字段说明

| 字段 | 必需 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一标识，小写字母+连字符 |
| `name` | ✅ | 显示名称（中文可以） |
| `version` | ✅ | 语义化版本 |
| `description` | ✅ | 一句话说明，会显示在插件列表 |
| `author` | ✅ | 作者 |
| `homepage` | | 项目地址 |
| `license` | | 许可证 |
| `icon` | ✅ | Material 图标名（见下方） |
| `category` | ✅ | 分类，用于分组 |
| `tools` | ✅ | 可执行工具列表（可以为空数组） |
| `ui` | ✅ | 界面定义 |
| `loaders` | | 特殊：EDL loader 目录（见第六节） |

### 2.3 图标名

用 Material Icons 的名字，常见：

```
star  build  memory  layers  phone_iphone  usb  settings
unarchive  terminal  bug_report  security  storage  android
```

完整列表：https://fonts.google.com/icons

## 三、工具声明

```json
"tools": [
  {
    "name": "mytool",
    "path": "tools/windows/mytool.exe",
    "platform": "windows",
    "executable": true
  },
  {
    "name": "mytool",
    "path": "tools/linux/mytool",
    "platform": "linux",
    "executable": true
  }
]
```

**同一个 `name` 可以有多个平台版本**，程序会按当前系统选。

### 重要：伴随文件

很多工具需要 DLL / so / 配置文件。**放在同一目录即可**，程序会把整个 `tools/<platform>/` 目录复制到工作区。

```
tools/windows/
├── mytool.exe
├── libfoo.dll        ← 伴随文件，自动带上
└── config.ini
```

### Linux 可执行位

zip 里可能丢失执行权限。程序会自动 `chmod +x`，不用手动设置。

## 四、UI 定义

### 4.1 输入（inputs）

```json
"inputs": [
  {
    "id": "file",
    "type": "file",
    "label": "输入文件",
    "hint": "选择要处理的文件",
    "filter": "img,bin"
  }
]
```

| 字段 | 说明 |
|---|---|
| `id` | 占位符里引用的名字，必须唯一 |
| `type` | `text` / `file` / `dir` / `select` / `bool` |
| `label` | 显示标签 |
| `hint` | 占位提示 |
| `filter` | `file` 类型用，指定扩展名（逗号分隔） |
| `options` | `select` 类型用，选项列表 |
| `default` | 默认值 |

**五种类型：**

```json
{ "id": "name",   "type": "text",   "label": "名称" }
{ "id": "path",   "type": "file",   "label": "文件" }
{ "id": "outdir", "type": "dir",    "label": "输出目录" }
{ "id": "mode",   "type": "select", "label": "模式",
  "options": ["fast", "safe", "debug"] }
{ "id": "opt",    "type": "bool",   "label": "启用优化" }
```

### 4.2 卡片与动作（cards）

```json
"cards": [
  {
    "title": "解包",
    "actions": [
      {
        "label": "解包镜像",
        "tool": "mytool",
        "args": ["unpack", "{input:file}", "-o", "{input:outdir}"],
        "timeout": 600,
        "confirm": "确定要解包吗？",
        "danger": false
      }
    ]
  }
]
```

| 字段 | 说明 |
|---|---|
| `title` | 卡片标题 |
| `actions` | 动作列表，每个动作是一个按钮 |
| `label` | 按钮文字 |
| `tool` | 用哪个工具（对应 `tools` 里的 `name`） |
| `args` | 参数数组，支持占位符 |
| `timeout` | 超时秒数（默认 1800） |
| `confirm` | 点击后弹确认框（可选） |
| `danger` | `true` 时按钮显示红色（表示有风险） |

## 五、占位符

`args` 数组里可以引用用户输入和路径：

| 占位符 | 替换成 |
|---|---|
| `{input:xxx}` | 用户填的值（`xxx` 是 input 的 id） |
| `{pluginDir}` | 插件目录绝对路径 |
| `{toolDir}` | 工具目录绝对路径（pluginDir/tools） |

### 示例

```json
"args": ["-f", "{input:payload}", "-o", "{pluginDir}/output"]
```

### 未填写的处理

**用户没填的 `{input:xxx}` 不会被替换**，程序会拦截并提示：

```
❌ 还有 1 个参数没填：「输入文件」
   请在「参数」区填写后重试。
```

这样工具永远不会收到 `{input:file}` 这种乱码。

## 六、EDL Loader 插件（特殊类型）

如果你有一批高通 EDL loader 想共享，用专门的格式：

### 6.1 目录结构

```
edl-loader-pack/
├── plugin.json
├── loader-index.json      ← 可选，加速加载
└── loaders/
    ├── xiaomi/
    │   ├── 000ba0e100720000_57158eaf1814d78f_fhprg_redmi7.bin
    │   └── ...
    ├── oppo/
    └── ...
```

### 6.2 plugin.json

```json
{
  "id": "my-loaders",
  "name": "我的 Loader 合集",
  "version": "1.0.0",
  "description": "自用的 EDL loader",
  "author": "你",
  "icon": "memory",
  "category": "刷机",
  "type": "edl-loader-pack",
  "loaders": "loaders/",
  "tools": [],
  "ui": { "inputs": [], "cards": [] }
}
```

关键字段：
- `"type": "edl-loader-pack"` — 声明这是 loader 包
- `"loaders": "loaders/"` — loader 目录（相对插件根）

### 6.3 文件名格式

```
HWID_PKHASH[:8]_类型[_机型].bin
```

例：
```
000ba0e100720000_57158eaf1814d78f_fhprg_redmi7.bin
└─────┬─────┘ └──────┬──────┘ └──┬──┘ └──┬──┘
    HWID         公钥哈希前8字节   类型    机型
```

类型：
- `fhprg` — 标准版（能读能写）
- `fhprg_peek` — 只读版（`program`/`erase` 会被设备拒绝）
- `fhprg_noauth` — 无签名版（仅老设备）

### 6.4 装了之后

EDL 页面会自动出现「自动匹配」按钮，按 HWID / 公钥哈希 / 机型名三级匹配。

**不装这个插件，EDL 页面完全没有这个按钮** —— 插件不影响核心界面。

### 6.5 预索引（可选）

878 个文件全扫描要几秒。可以在插件根目录放 `loader-index.json`：

```json
{
  "version": 1,
  "total": 3,
  "loaders": [
    {
      "path": "xiaomi/000ba0e1_57158eaf_fhprg_redmi7.bin",
      "hwid": "000ba0e100720000",
      "pkhash": "57158eaf1814d78f",
      "type": "fhprg",
      "model": "redmi7",
      "size": 634880
    }
  ]
}
```

有预索引时，加载从**几秒降到 66 ms**。

## 七、时长常驻进程（如端口转发）

有些工具不会退出（`iproxy` 监听端口）。用大 timeout：

```json
{
  "label": "启动端口转发",
  "tool": "iproxy",
  "args": ["8100", "8100"],
  "timeout": 1800
}
```

点「执行」后会一直跑，日志实时显示。点「停止」或超时才结束。

## 八、调试技巧

### 8.1 先单独测试工具

在命令行里先跑通，再放进插件：

```bash
cd tools/windows
./mytool.exe --help
```

### 8.2 看日志

执行动作后，「输出」区会显示所有 stdout/stderr。
如果工具没输出，可能是：

- 缺 DLL（Windows）→ 用 `WINEDEBUG=+loaddll` 在 wine 里能看到
- 缺执行权限（Linux）→ 程序会自动 chmod，但如果还不行手动加
- 参数被拦截 → 看是否有「还有 N 个参数没填」提示

### 8.3 检查清单

导入前自查：

- [ ] `plugin.json` 是合法 JSON（用 `python3 -m json.tool plugin.json` 验证）
- [ ] 每个 `tools[].path` 的文件真实存在
- [ ] 同一个工具的 Windows/Linux 版本都用相同的 `name`
- [ ] `args` 里的 `{input:xxx}` 对应的 input id 真实存在
- [ ] `icon` 是有效的 Material 图标名

## 九、发布

### 9.1 打包

**关键：从插件目录内部打包，不要带外层目录。**

```bash
cd my-plugin
zip -r ../my-plugin.zip . -x "*.DS_Store"
```

验证结构：

```bash
unzip -l ../my-plugin.zip | head -5
# 应该看到 plugin.json 在根目录，不是 my-plugin/plugin.json
```

### 9.2 分享

把 zip 发给别人，对方在「插件管理」→「导入」选择 zip 即可。

## 十、完整示例：payload-dumper 插件

```
payload-dumper-plugin/
├── plugin.json
└── tools/
    ├── windows/payload-dumper-go.exe
    └── linux/payload-dumper-go
```

`plugin.json`：

```json
{
  "id": "payload-dumper-go",
  "name": "OTA Payload 解包",
  "version": "1.0.0",
  "description": "从 Android OTA 包中提取 payload.bin 内的分区镜像",
  "author": "ssut",
  "homepage": "https://github.com/ssut/payload-dumper-go",
  "license": "Apache-2.0",
  "icon": "unarchive",
  "category": "刷机",
  "tools": [
    {
      "name": "payload-dumper",
      "path": "tools/windows/payload-dumper-go.exe",
      "platform": "windows",
      "executable": true
    },
    {
      "name": "payload-dumper",
      "path": "tools/linux/payload-dumper-go",
      "platform": "linux",
      "executable": true
    }
  ],
  "ui": {
    "inputs": [
      {
        "id": "payload",
        "type": "file",
        "label": "payload.bin / OTA 包",
        "hint": "OTA zip 或解包后的 payload.bin",
        "filter": "bin,zip"
      },
      {
        "id": "outdir",
        "type": "dir",
        "label": "输出目录",
        "hint": "解出的镜像存放位置"
      },
      {
        "id": "parts",
        "type": "text",
        "label": "只解这些分区",
        "hint": "逗号分隔，如 boot,system；留空解全部"
      }
    ],
    "cards": [
      {
        "title": "解包",
        "actions": [
          {
            "label": "全部解出",
            "tool": "payload-dumper",
            "args": ["-o", "{input:outdir}", "{input:payload}"],
            "timeout": 1800
          },
          {
            "label": "只解指定分区",
            "tool": "payload-dumper",
            "args": [
              "-o", "{input:outdir}",
              "-p", "{input:parts}",
              "{input:payload}"
            ],
            "timeout": 1800
          }
        ]
      }
    ]
  }
}
```

## 十一、常见问题

**Q: 插件装在哪里？**

- Windows: `%LOCALAPPDATA%\io.github.flashallinone\plugins\`
- Linux: `~/.local/share/io.github.flashallinone/plugins/`

**Q: 插件能访问网络吗？**

能。插件执行的是普通进程，不受限制。但主程序自己不联网。

**Q: 插件能改主程序界面吗？**

不能。插件只能提供工具 + 声明式 UI，无法修改主程序的页面逻辑。

**Q: 多个插件同名工具会冲突吗？**

不会。每个插件的工具在自己的目录下，互不干扰。

**Q: 支持 macOS 吗？**

主程序目前只支持 Windows / Linux。插件里的 `platform` 字段暂时只识别这两个。
